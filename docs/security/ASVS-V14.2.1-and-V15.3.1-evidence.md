# ASVS V14.2.1 and V15.3.1 implementation evidence

Date: 20 September 2026  
Scope: Sentinel server code. Deployment controls and the separately configured
browser Maps key are outside this evidence record.

## V14.2.1 — sensitive data in URL parameters

### Finding addressed

`GoogleLocationLookupService` previously used legacy Google Maps web-service
URLs and supplied the server-side `Geocoding:ApiKey` as a `key` query-string
parameter. Query strings are routinely present in proxy, application and
browser-adjacent request logs, so this could disclose a server credential.

### Remediation

The server-side client now uses the current Google endpoints:

- Geocoding API v4: `https://geocode.googleapis.com/v4/geocode/...`
- Places API (New) autocomplete, text search and place details endpoints.

`GoogleLocationLookupService` creates each request with the server key only in
the `X-Goog-Api-Key` request header. It sends a minimal `X-Goog-FieldMask` on
each Google request, so the service asks only for address/place data it needs.
`Program.cs` no longer configures the retired Maps API v3 base URL.

The remaining `maps.googleapis.com/...key=` occurrence is deliberately in
`wwwroot/js/geocoding.js`: it uses `GOOGLE_MAPS_BROWSER_API_KEY`, a distinct
browser-visible key required by the Maps JavaScript SDK. It must be restricted
by HTTPS referrer and API in Google Cloud. The server-only key must instead be
restricted to the server's egress IPs; the comments in `.env.example` now make
that distinction explicit.

### Verification

`Sentinel.Tests/Services/GoogleLocationLookupServiceTests.cs` uses a recording
HTTP handler. The tests prove that the Geocoding, autocomplete/details and
text-search calls:

- use the current Google endpoint;
- contain the server key in `X-Goog-Api-Key`;
- do not put the key in the request URL or JSON body; and
- request a defined field mask.

Static scan used after the change:

```powershell
rg -n --glob '!bin/**' --glob '!obj/**' --glob '!bin_temp/**' \
  "maps\\.googleapis\\.com|geocode/json|place/autocomplete/json|place/details/json|[?&]key=|X-Goog-Api-Key" \
  Sentinel -g '*.cs' -g '*.js' -g '*.cshtml' -g '*.json'
```

It found no server-side legacy request URL or server key in a URL. The only
query-string key is the intentionally public browser SDK key described above.

## V15.3.1 — response and export safety inventory

### Line List endpoints

The Line List endpoints were the highest-risk response/export surface because
they expose patient and case values in a configurable grid.

| Endpoint | Response protection |
|---|---|
| `GET /api/LineList/fields/{outbreakId}` | Returns `LineListFieldResponse` only: path, display metadata and flags. Requires accessible outbreak. |
| `POST /api/LineList/data` | Returns `LineListDataResponse` only: case/outbreak IDs and values for configured field paths. Both controller and service reject non-configured paths. |
| `GET /api/LineList/configurations/{outbreakId}` | Returns `LineListConfigurationsResponse`; user and shared configurations are explicitly mapped, excluding ownership/audit/entity navigation properties. |
| `POST /api/LineList/configurations` | Returns the same explicit configuration DTO. The server ignores caller-supplied ownership and audit properties. |
| `POST /api/LineList/export` | Requires `Outbreak.Export`, accessible outbreak, and configured field paths. Exports CSV as `text/csv; charset=utf-8`. |

The service's `ExtractFieldValue` is a closed switch over configured, scalar
field paths. It does not reflect arbitrary model properties. `ExportToCsvAsync`
also obtains the allow-list defensively, so a future caller cannot bypass the
controller check.

CSV cells beginning with `=`, `+`, `-`, `@`, tab or carriage return are
prefixed with an apostrophe before ordinary CSV escaping. This prevents
spreadsheet applications interpreting user-controlled values as formulas.

### Other controller response surfaces reviewed

The controller inventory was generated by searching `return Ok(` and
`return File(` in `Sentinel/Controllers` and relevant Razor handlers. The
following use explicit anonymous projections, named response models, metadata
models, or protected byte streams rather than directly serializing tracked EF
entities:

- Case, patient, disease, event, location and country lookup APIs project the
  exact lookup/display fields.
- Survey version, custom-field, collection-mapping and survey-mapping APIs
  project version/configuration metadata and validation responses.
- Reporting APIs return report field metadata or dedicated report response
  contracts; report data access is separately subject to entity and
  disease-hierarchy access controls.
- HL7 diagnostics deliberately exposes the diagnostic model only to
  `HL7.View`; its message-detail response is an explicit, limited projection.
- Location lookup maps server-side geocoding results to an explicit address or
  place response; no provider credential is returned.
- `ProtectedAttachmentsController` performs object-level access checks before
  returning a file stream. The population template is static CSV output.

The remaining `return File(...)` inventory contains only the protected
attachment download, Line List CSV export and static population CSV template.

### Verification

The focused suite was run from an isolated build copy while the developer
instance held the main executable open:

```powershell
dotnet test Sentinel.Tests/Sentinel.Tests.csproj --no-restore --filter \
  "FullyQualifiedName~GoogleLocationLookupServiceTests|FullyQualifiedName~LineListCsvExportTests|FullyQualifiedName~ApiResponseContractTests|FullyQualifiedName~LineListObjectAccessTests" \
  --verbosity minimal
```

Result: **23 passed, 0 failed**.

The test coverage includes explicit Line List contract assertions, rejection of
an unconfigured `Patient.PasswordHash` field path before data extraction,
cross-user configuration ownership checks, and CSV formula/quoting behaviour.

## Remaining operational check

After the application is rebuilt, perform one UI smoke test of an accessible
outbreak Line List: load fields, save a shared view, reload configurations and
export a CSV. This is a compatibility check, not an unresolved server-side
security control; the response property names have been kept compatible with
the prior client contract.
